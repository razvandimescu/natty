Connect to a peer behind NAT by its key

An application reaches its peer by public key, through a relay that both peers use. When the two NATs allow it, the peers open a direct UDP path through them (hole punching). When they do not, the relay forwards the encrypted packets.

An opener is a UDP packet with TTL 2. It opens the local NAT to the peer.

three parts

Start with the part you need

library

Use it in a Rust application that must reach a peer. It gives the application a quinn::Connection to a peer key.

# Cargo.toml
natty = "0.0.3"

// The handshake fails unless the
// peer holds the key `peer`.
let conn = endpoint.connect(peer).await?;
let (mut send, recv) =
    conn.open_bi().await?;
send.write_all(b"hello").await?;

CLI

Use it to share a TCP service from a machine with no inbound port. A grants file lists the keys for each service.

# On both machines
cargo install natty --features cli
export NATTY_KEY="$HOME/.natty/key"

# On the machine with the service
natty serve relay.example.net \
  --grants grants \
  --service web=127.0.0.1:8000

# On the other machine
natty connect \
  '<key>@relay.example.net' web \
  --port 8080
Share a service →

relay

Run it on a host that both peers can reach. It forwards packets by key and answers STUN requests.

cargo install natty-relay

natty-relay --cert fullchain.pem \
  --key privkey.pem

# The answer is ok.
curl https://relay.example.net/health

privacy

What the relay sees and what it counts

The relay code has no per-session log path. It keeps only aggregate counters. Only the relay host can read them. A new relay gives this answer:

$ curl --resolve relay.example.net:443:127.0.0.1 \
    https://relay.example.net/health
ok
uptime_secs 0
sessions 0
sessions_total 0
auth_failed 0
conns_rejected 0
forwarded_frames 0
forwarded_bytes 0
dropped_frames 0
peer_gone 0
stun_responses 0

natty has no default relay. Each application chooses its own.

Visible to the relay

relay.example.net

  • onlineThe keys that are online, and their addresses.
  • sessionsWhen each session starts and stops.
  • pairsWhich pairs of keys exchange packets, and the byte counts.
  • alpnThe ALPN of each connection. The first QUIC packet is not confidential.
  • punchThe local and public addresses and the probe keys of peers that punch.
  • payloadThe relay does not see the QUIC payload.

Any peer that knows <key>@<relay> can open a connection through the relay. That peer learns that the endpoint is online.

scope

Scope and status

natty is for applications that already have the address of each peer: its key and its relay.

Use a different tool when you need

  • Discovery or lookup of keys. natty never publishes or searches for keys.
  • A mesh, a VPN or an overlay network, for example Tailscale or ZeroTier.
  • Connections to browsers, for example WebRTC.
  • Access without natty on the client side, for example a public URL.
  • A tunnel for UDP services. The CLI forwards only TCP.
